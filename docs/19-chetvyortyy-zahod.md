# Четвёртый заход: вторая проверка на прочность

Первая проверка (см. [16](16-audit-i-novoe.md)) закрыла крупные дыры. За
три захода после неё в проекте появились подписки, код отметки, «Точно
выйду», доплаты за правку. Каждая новая возможность — новые места, где
деньги и правила могут разойтись. Поэтому проект прочитали ещё раз
целиком, тремя заходами сразу: ядро и деньги, сервер и права, экраны.

## 1. Деньги и правила записи

| Что было | Чем грозило | Как теперь |
|---|---|---|
| Возврат читал «сколько уже вернули», ждал провайдера и записывал сумму | две отметки «не вышел» разом теряли один возврат в учёте, и потом остаток смены возвращался заказчику **второй раз** | сумма откладывается одной командой `refunded = refunded + ?` с условием «не больше, чем взяли», и только потом идёт к провайдеру. Остаток смены забирается условием «если ещё держим» |
| Невыход можно было поставить тому, кто отметился кодом | заказчик забирал заработок человека, который был на месте | отказ `checkedIn`: код видно только на точке, спорный случай разбирает поддержка |
| Доплата за правку, пришедшая после начала смены, всё равно меняла условия | смену «10:00 сегодня» переносили на завтра посреди работы | такая доплата возвращается целиком (`refundNotApplied`) |
| Пометку «заменена новой правкой» проверяли по копии оплаты | опрос оплат держит копии минутной давности — старая правка могла вступить в силу | пометку читают из базы после того, как оплата стала «оплаченной» |
| Заказчик мог записаться на свою смену | сам подтверждал себе выход, получал заработок и оставлял отзыв о своей компании | отказ `ownShift` |
| Код отметки — четыре цифры без счётчика | скрипт из дома перебирал 10 000 вариантов и получал «на месте · код» | пять попыток на запись, счётчик прибавляется одной командой (`check_in_attempts`, схема 22) |
| Ночная смена 22:00–06:00 после полуночи пропадала из «В работе», отметиться было нельзя | пришедший в 00:10 человек оставался без отметки | «В работе» — пока смена не кончилась; отметка — до конца смены, у ночной — до утра |
| Повторная запись сохраняла старое «Точно выйду» | заказчик видел подтверждение, которого никто не давал | повторная запись начинается с чистого листа |
| 10:00–10:00 принималось как смена на сутки | опечатка стоила заказчику 23 оплаченных часа на место | время начала и конца должно различаться |
| Первая демо-смена на пустой базе записывала людей с номерами 100–103 | настоящие пользователи с этими номерами видели себя записанными на чужие смены | демо-люди только с отрицательными номерами |

### Тестовая оплата при настоящих выплатах

Сервер может работать «наполовину»: карты и выплаты через ioka настоящие,
а Kaspi ещё тестовый. В таком режиме смену можно было «оплатить»
тестовым Kaspi, а заработок за неё вывести на карту живыми деньгами.

Теперь правило одно и живёт в шлюзе: `PaymentGateway.accepts(method)`.
Тестовый способ принимается, только если и выплаты тестовые. Иначе
оплата этим способом отклоняется сразу, ещё до создания операции, с
понятной причиной: «Этот способ оплаты пока не подключён».

### Индексы

В базе не было ни одного индекса, кроме уникальных ключей. Число на
колокольчике, «Мои смены», опрос оплат раз в минуту и напоминания раз в
час читали таблицы целиком. Индексы заводятся при каждом открытии базы
командой `CREATE INDEX IF NOT EXISTS` — её понимают и SQLite, и
PostgreSQL, поэтому номер схемы ради них не поднимали.

## 2. Сервер

| Что было | Как теперь |
|---|---|
| Тело запроса читалось целиком, сколько ни пришли | не больше 64 КБ, иначе 413; байты считаются при чтении, заголовку не верим |
| Кривой JSON на адресах без входа (`/auth/*`) ронял обработчик — 500 | общая проверка перед всеми адресами отвечает 400 |
| Сбой платёжного сервиса посреди возврата — 500 | 502 «платёжный сервис не ответил», подробности в журнал |
| «Не больше пяти кодов в час» читал счётчик, ждал письмо 15 секунд и только потом записывал | строка с кодом заводится **до** отправки; из одновременных запросов проходит первый. Сто запросов разом — одно письмо |
| Коды можно было запрашивать подряд | новый код не раньше чем через минуту после прошлого |
| При регистрации роль и город брались как есть | роль — исполнитель или заказчик, город — из списка, у заказчика обязательна компания |
| Старое приложение падало на новом ответе сервера при правке смены | незнакомый ответ читается как «не нашлось» |

## 3. Экраны

Экран честен, когда на любой сбой отвечает понятно и не даёт сделать
одно и то же дважды. Нашлись места, где это было не так.

| Что было | Как теперь |
|---|---|
| Смена по ссылке, компания, документы, поддержка на плохой связи — вечный кружок | ошибка с «Повторить»; сбой перечитывания не прячет уже показанное |
| После сбоя перечитывания кнопка действия оставалась крутиться | перечитывание не бросает, кнопка оживает |
| По уведомлению «смену отменили» открывалась смена с кнопкой «Записаться» | «Смена отменена заказчиком», после невыхода — «Заказчик отметил невыход» |
| Упал рейтинг — своя записанная смена не открывалась: ни отметиться, ни отменить | порог рейтинга закрывает только чужие смены |
| Закрыли окно оплаты, пока ждали Kaspi, — экран делал вид, что ничего не было, и повторное «Оплатить» создавало вторую смену | окно возвращает последнюю оплату и в любом случае говорит «смена сохранена, ждёт оплаты»; смахнуть окно посреди запроса нельзя |
| Два ответа «оплачено» подряд закрывали окно дважды — и экран под ним | окно закрывается один раз, опрос не наслаивается |
| Запросы к серверу не имели предела ожидания | минута: столько просыпается бесплатный сервер, дальше — «сервер не ответил» |
| Без связи или с просроченным токеном нельзя было выйти из аккаунта | выход всегда стирает токен на телефоне, сервер — лишь вежливость |
| Быстро тапнули два дня подряд — смены одного дня ложились под заголовок другого | показывается только ответ на последний запрос |
| Архив спрашивал «оставлен ли отзыв» по каждой смене по очереди | только про отработанные и разом |
| Два переключателя подписок подряд затирали друг друга | новый набор считается от нынешнего |
| Двойной Enter на входе слал два письма с кодом | шаг входа не запускается, пока идёт прошлый |
| «Вышел» отпускал деньги с одного касания, без вопроса | спрашивает «Засчитать выход?» с суммой; кнопки погашены, пока идёт запрос |
| Сообщение в поддержку стиралось из поля до отправки — при сбое пропадало | поле чистится после того, как сообщение ушло; пустое обращение не отправить |
| В переписке свежее сообщение было внизу длинного списка | список открывается на последнем сообщении |

Потянуть вниз теперь можно в «Моих сменах», в выплатах, в поддержке и в
списке записавшихся — там, где человек ждёт чужого действия: подтверждения
выхода, выплаты, ответа.

Экранный чтец больше не говорит пять раз «кнопка» на звёздах отзыва — у
каждой своя подпись. Дни в полосе дат и вкладки «В работе / Архив»
объявляются кнопками с отметкой «выбрано».

## 4. Удобство заказчика

**Сначала то, что впереди.** Список смен заказчика шёл одной лентой «новые
даты сверху», и сегодняшняя смена оказывалась под всеми будущими. А как
раз на ней нужны код отметки и кнопки «Вышел». Теперь список делится на
два раздела. «Впереди»: ближайшая смена первой. «Прошедшие и отменённые»:
свежие первыми. Правило живёт в модели (`splitByTime`) и проверено
тестом.

**Форма одежды и порог рейтинга в форме смены.** Хранилище, сервер и
экран исполнителя понимали оба поля давно, но задать их в форме было
негде. Повтор смены к тому же терял форму одежды образца. Теперь в форме
есть раздел «Требования»: форма одежды и «Кого пускать на смену» (все,
от ★ 4.0, от ★ 4.5). Порог задаётся только при создании: у уже
записавшихся он проверен, и менять его задним числом было бы нечестно.
Сервер принимает порог только от 1 до 5.
