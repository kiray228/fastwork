# Проверка на прочность и что появилось после неё

Этот раздел про большой проход по проекту. Сначала код читали, как
читает его злоумышленник или невнимательный пользователь. Потом
приложение прошли в браузере как живой человек. Потом смотрели, что есть
у конкурентов. Всё найденное исправлено, лучшее у конкурентов перенято.

## 1. Что было сломано

### Деньги и жизненный путь записи

| Что было | Чем грозило | Как теперь |
|---|---|---|
| Повторная запись возвращала подтверждённую смену в `active` | выход подтверждали и **оплачивали дважды**; невыход так же стирался | заново записаться можно только после своей отмены (`alreadyFinished`) |
| Записаться можно было на смену, которая уже идёт или прошла | запись «в прошлое» | только до начала (`alreadyStarted`), а начавшиеся смены пропали из ленты |
| Две смены в одно время | человек не может быть в двух местах | пересечение по времени запрещено (`timeConflict`), ночные смены учтены |
| «Отменить запись» перезаписывала любой статус | можно было стереть невыход; заказчику летело «человек снял запись» от тех, кто не записывался | снять можно только живую запись |
| Двойное нажатие «Вышел» | две выплаты (проверка и запись — два шага) | условие `status = active` прямо в `UPDATE`: второй запрос ничего не находит |
| Выход и невыход можно было отметить до начала смены | невыход «заранее» и возврат денег заказчику | только после начала (`notStarted`) |
| Заказчик мог править и отменять смену, пока люди работают | урезать ставку посреди смены; отменить в 21:00 и забрать всё | после начала условия заморожены |
| Деньги за места, на которые никто не записался, возвращались только при отмене | смена прошла как обычно — остаток навсегда у сервиса | последняя отметка закрывает смену и возвращает остаток сама |
| Две подорожавшие правки подряд | заказчик переплачивал; старая доплата могла откатить смену назад | новая правка отменяет прошлую доплату, а если её всё же оплатили, деньги возвращаются |

### Кто что может

Запрос можно отправить и без приложения, подставив чужой номер. Сервер
таким запросам верил:

| Дыра | Как теперь |
|---|---|
| Список записавшихся с телефонами видел любой вошедший | только заказчик этой смены |
| Любой заказчик мог ставить оценки кому угодно и «топить» рейтинг | только своему исполнителю и только за подтверждённый выход |
| Отзыв о компании мог оставить кто угодно | только тот, кто там отработал |
| Чужие обращения в поддержку можно было читать и дописывать | только свои |
| Чужие документы можно было одобрить или отклонить | только свои |
| Три попытки ввода кода не держали параллельных запросов; один код подходил дважды | попытка засчитывается одной командой «прибавь, если ещё можно» |
| Вход по токену был вечным | 90 дней |
| Отрицательная ставка, ноль мест, смена в прошлом принимались | общие правила формы (`shiftFormError`) проверяет и экран, и сервер |
| Компания смены бралась из запроса | из профиля заказчика: от имени «Magnum» смену не выставить |
| Кривой запрос ронял обработчик (500) | ответ 400 с понятным текстом |
| Сервер считал время по UTC | контейнер живёт по `Asia/Almaty`: иначе отметка открывалась на 5 часов позже |

### Что нашлось в браузере

- **Лента пустела навсегда.** Демо-смены заводились один раз, от дня
  первого запуска. Через неделю они все оказывались в прошлом. А в
  Астане, Караганде, Актобе и Таразе их не было вовсе. Теперь
  `keepDemoFresh()` держит смены на неделю вперёд во всех шести городах.
  Сервер обновляет их раз в час, телефон — при запуске. Выключается
  через `DEMO_SHIFTS=off`.
- **Демо-люди с номерами от сотого.** Это пересекалось с настоящими
  пользователями: сотый человек на сервере увидел бы себя записанным на
  чужую смену. Теперь номера у демо-людей отрицательные.
- Точка «тут есть смены» стояла под днём, все смены которого уже
  начались.
- Окно записи обещало «отменить можно до 05:00», когда 05:00 уже прошло.
- В профиле было написано «2 смен». Теперь правило окончаний одно на всё
  приложение (`plural`).
- Подпись у галочки переносилась кусками, и строка начиналась с
  «, включая…». Заказчику при этом показывали лимит дохода исполнителя.
- Карточка заполненной смены была мёртвой кнопкой «Мест нет».

## 2. Тесты, которые не зависят от часов

Правила теперь зависят от времени. Тест на настоящих часах проходил бы
утром и падал вечером. Поэтому хранилища получают часы снаружи:

```dart
final clock = TestClock.today();          // сегодня, 06:00
final repo = FakeShiftRepository(clock: clock.call);
await repo.apply(1);                      // смена в 10:00 — ещё впереди
clock.setHour(23);                        // «дожили» до вечера
await repo.confirmAttendance(...);        // теперь подтверждать можно
```

Это тот же приём, что у `canCancelAt(now)` в модели: время передаётся
параметром. Ещё добавлена проверка в GitHub Actions (`check.yml`). На
каждую ветку и pull request она запускает анализ кода и все три набора
тестов, включая серверные, которые раньше не запускал никто.

## 3. Что взяли у конкурентов

Смотрели EasyTap, GigAnt, Smena, Яндекс Смену, OVork, Instawork, Wonolo,
Coople, Indeed Flex, Shiftsmart, Qwick. Отбирали то, что даёт много пользы
при малой цене и не требует сторонних сервисов.

| Что | У кого есть | Как сделано у нас |
|---|---|---|
| **Как добраться** | Smena, Яндекс Смена, Instawork | кнопка на смене открывает адрес в 2ГИС, Яндекс Картах или Google Картах. Ссылки обычные https: есть приложение — откроется оно, нет — сайт |
| **В календарь** | Instawork | записанную смену можно добавить в Google Календарь: место, сумма, срок отмены, а календарь сам напомнит |
| **Повторить смену** | Instawork, Coople (шаблоны) | «Повторить» на любой смене заказчика: форма заполнена по образцу и стоит на завтра |
| **Любимые исполнители** | Instawork, Wonolo, Coople, Qwick, Indeed Flex | сердечко у отработавшего. Когда смена опубликована, любимым из того же города приходит приглашение. Список — в профиле заказчика |
| **Лист ожидания** | Instawork | на заполненной смене кнопка «Сообщить, когда освободится». Освободилось место — уведомление всем ждущим, записывается тот, кто успел |
| **Напоминание накануне** | почти у всех | за сутки до смены — одно уведомление со временем, адресом и просьбой отметиться |
| **Заработок по неделям** | Instawork, Яндекс Смена | график в «Выплатах»: восемь недель, сумма, среднее, касанием — неделя подробно |

Второй заход:

| Что | У кого есть | Как сделано у нас |
|---|---|---|
| **Подписка на компанию** | Coople, Яндекс Смена (сохранённые фильтры) | «Сообщать о новых сменах» на странице компании: новая смена этой компании в вашем городе приходит уведомлением. На той же странице — ближайшие смены компании |
| **Ссылка на смену** | Instawork, Smena | «Поделиться» кладёт в текст ссылку `…/fastwork/?shift=12`: по ней друг сразу видит смену, даже если ещё не зарегистрирован |
| **«Срочно» и «Без отмены»** | GigAnt, EasyTap (срочные заявки) | ярлыки считаются из времени: смена в ближайшие сутки со свободными местами — «Срочно»; срок отмены уже прошёл — «Без отмены», и это видно до записи |
| **Сводка заказчика** | Instawork, Indeed Flex | над «Моими сменами»: смены за 30 дней, процент занятых мест, расходы за месяц |
| **Код отметки** | Instawork, Jobandtalent (геозона, QR) | у заказчика на экране «Записались» — четыре цифры. Исполнитель вводит их в «Я на месте», и отметка помечается «На месте · код» |

Чего не взяли и почему:

- **Отметка по геолокации или QR** — нужны пакеты для геолокации и
  камеры, а у нас только `url_launcher`. Код отметки закрывает ту же
  задачу без них: код видно только на точке.
- **Карта смен** — нужен SDK карт с ключами и платой за запросы.
- **Мгновенный вывод за комиссию** — это решение о деньгах, а не о коде.
- **Реферальная программа** — тоже вопрос денег и правил.

## 4. Что осталось — сознательно

- **Документы одобряются сами.** Загрузил удостоверение — через пару
  секунд оно «принято». Это учебная замена проверки: оператора, который
  смотрел бы документы, у проекта нет. Чужой документ одобрить больше
  нельзя, но свой человек по-прежнему одобряет сам. Значок «Верифицирован»
  у исполнителя поэтому пока ничего не доказывает.
- **Возврат денег внутри транзакции базы.** При отмене смены или
  подешевевшей правке возврат у провайдера идёт по сети внутри транзакции.
  Если после него транзакция откатится, деньги уйдут, а записи о возврате
  не будет. Случай редкий: откат после успешного возврата требует сбоя
  базы в ту же секунду. Правильное решение — журнал «намерений вернуть»,
  который отрабатывается после транзакции. Это заметная переделка, её
  стоит делать вместе с подключением настоящих денег.
- **Заказчиком может зарегистрироваться любой.** Так задумано: заказчики
  приходят сами. Защита от фальшивых компаний — оплата заранее: смена без
  денег в ленту не попадает.
