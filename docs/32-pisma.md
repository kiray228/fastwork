# Письма о сменах

Уведомления жили только в колокольчике приложения: человек узнавал о
них, когда открывал приложение. Приглашение на завтрашнюю смену,
«освободилось место», отмена смены за три часа до начала — всё это
теряет смысл, если прочитано вечером. Пуш-уведомлений у веб-версии нет,
а на телефоне для них нужен отдельный сервис. Почта же есть у каждого:
по ней человек входит.

## Что приходит письмом

Важные уведомления дублируются письмом на почту входа:

| Уведомление | Предел |
|---|---|
| приглашение на смену | 3 в день вместе с остальными |
| новая смена (подписка, свободный день) | 3 в день |
| освободилось место (лист ожидания) | 3 в день |
| выход подтверждён, деньги начислены | 3 в день |
| сообщение в переписке по смене | 3 в день |
| смену отменили | всегда |
| смену изменили | всегда |
| напоминание о смене | всегда |
| заказчику: человек снял запись | всегда |
| заказчику: на смену не хватает людей | всегда |
| заказчику: кто-то записался | 3 в день |

Отмена, изменение и напоминание — про смену, на которую человек уже
записан. Пропустить их дороже, чем получить лишнее письмо, поэтому они
приходят всегда. Остальным — не больше трёх писем в день: дальше это
уже рассылка, от которой отписываются целиком.

В письме: заголовок уведомления — в теме, его текст, ссылка «Открыть в
fastwork» прямо на смену и строка о том, как отключить письма. Всё на
языке, на котором человек пользуется приложением.

## Отключить

Профиль → **«Письма о сменах»**. Переключатель есть только у тех, кто
входит по почте. В колокольчике приложения уведомления остаются как
были.

## Как устроено

- Решение «какие письма слать» — в ядре: `takeNoticeEmails`
  (`packages/core/lib/data/notice_mail.dart`). Каждое уведомление
  решается один раз: `notification_rows.email_state` ставится условным
  обновлением («если ещё не решали»), поэтому два запуска подряд одно
  письмо дважды не пошлют. Уведомления старше 6 часов письмом не
  дублируются: проснувшийся сервер не завалит человека устаревшими.
- Отправка — на сервере, раз в минуту, отдельно от запросов
  (`lib/notice_emails.dart`). Те же почтовые сервисы, что для кода
  входа (Brevo или SMTP), через общий `NoticeMailer`. Без почты — одна
  строка в окно сервера.
- Не ушло — не повторяем: уведомление осталось в приложении, а сбой
  почты не превратится в пачку одинаковых писем.
- Ссылка ведёт на `APP_URL` (по умолчанию сайт на GitHub Pages).
- Схема 29: `user_rows.email_notices`, `notification_rows.email_state`;
  `POST /api/me/email-notices`.

## Проверено

- Ядро: три письма в день и отмена сверх предела, неважные и устаревшие
  не шлются, повторный запуск пуст, предел обновляется назавтра; без
  почты, с отпиской и у удалённых — не пишем.
- Сервер: письмо по-казахски для казахскоязычного, ссылка на смену и
  отписка в тексте; переключатель через API.
- Экран: переключатель в профиле, у пользователя без почты его нет.
