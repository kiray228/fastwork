# 9. Приложение на телефоне

Как из кода получается файл, который можно скачать и поставить на Android.

---

## 9.1. Где скачать

**https://github.com/kiray228/fastwork/releases/latest**

Там лежит файл вида `fastwork-1.0.7.apk`. Открой эту страницу **с
телефона**, нажми на файл, разреши установку — и приложение на месте.

Ставить ничего заранее не нужно: ни Android Studio, ни эмулятора.

---

## 9.2. Что такое APK

`.apk` — это один файл, внутри которого лежит собранное приложение:
скомпилированный код, картинки, шрифты и описание прав, которые оно
просит у телефона. Примерно как `.exe` в Windows, только для Android.

Обычно приложения ставят из Google Play, и тогда APK человек не видит —
магазин скачивает его сам. Но поставить APK напрямую тоже можно, просто
Android один раз переспросит: «точно ставим из этого источника?».

---

## 9.3. Почему собирает GitHub, а не ноутбук

Чтобы собрать APK, нужен **Android SDK** — набор инструментов Google
весом в несколько гигабайт. Ставить его ради одного файла не хочется.

У GitHub эти инструменты уже стоят на его машинах. Поэтому сборка живёт
в файле `.github/workflows/release-apk.yml`: при каждом пуше в `main`
GitHub берёт код, собирает APK и кладёт его в раздел Releases.

То же самое, что происходит с сайтом — только там на выходе веб-страница,
а здесь файл для телефона. Один и тот же код, две разные упаковки:

```
          код в репозитории
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
  deploy-web.yml      release-apk.yml
        │                   │
        ▼                   ▼
   GitHub Pages       GitHub Releases
   (сайт в браузере)  (файл .apk)
        │                   │
        └─────────┬─────────┘
                  ▼
        сервер на Render + PostgreSQL
```

Обрати внимание на нижнюю стрелку: **сервер один**. Аккаунт, который ты
завёл на сайте, работает и в приложении на телефоне — это тот же аккаунт
в той же базе. Ради этого в обе сборки передаётся один и тот же адрес
сервера через `--dart-define=API_URL=...`.

---

## 9.4. Почему файл весит 60 МБ

Внутри APK лежит машинный код, и он у каждого типа процессора свой.
Телефоны бывают на `arm64`, на старом `arm` и (редко) на `x86_64`.
По умолчанию Flutter кладёт в файл **все три** — такой APK называется
универсальным и встанет на любой телефон.

Можно попросить `--split-per-abi`, и тогда получится три файла по ~20 МБ.
Но тогда придётся выбирать, какой скачивать, а ошибиться легко. Пока
приложение ставишь ты сам с одной ссылки, один файл на всех удобнее.
В Google Play такого выбора не возникает: магазин сам отдаёт телефону
нужную часть.

---

## 9.5. Про подпись

Каждый APK подписан ключом — это защита от подмены: Android не даст
обновить приложение файлом, подписанным **другим** ключом.

Мы подписываем отладочным ключом, который GitHub создаёт заново на каждой
сборке. Значит, ключ каждый раз новый, и поставить новую версию поверх
старой не получится — Android откажется. Лечится просто: удалить старую
и поставить заново. Данные не потеряются, они на сервере.

Как делают по-настоящему: один раз создают свой ключ, кладут его в
секреты репозитория и подписывают им все сборки. Тогда обновления
встают поверх. Это следующий шаг, когда приложение перестанет быть
учебным — без своего ключа в Google Play всё равно не пустят.

---

## 9.6. А iPhone?

Нет, и это не про наш код.

Собрать приложение для iOS может только **macOS** — таково требование
Apple, обойти его нельзя. Плюс аккаунт разработчика, 99 $ в год, и
установка только через App Store или TestFlight: просто скинуть файл,
как APK, Apple не разрешает.

При этом код у нас общий: тот же самый проект на Flutter собирается и
под iOS. Не хватает только машины и аккаунта.

Пока iPhone открывает сайт — **https://kiray228.github.io/fastwork/**.
Это то же приложение, только в браузере, и его можно добавить на главный
экран: «Поделиться» → «На экран „Домой“». Иконка будет как у обычного
приложения.
