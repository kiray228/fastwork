# 9. Приложение на телефоне

Как из кода получается файл, который можно скачать и поставить на Android.

---

## 9.1. Одна ссылка на всё

**https://kiray228.github.io/fastwork/install.html**

Открой её **с телефона**. Страница сама определит, Android у тебя или
iPhone, и покажет ровно то, что нужно: кнопку «Скачать» или четыре шага
для Safari.

Почему одна ссылка, а не две. Человеку, которому ты даёшь приложение,
не приходится выбирать — и не приходится объяснять, чем Android
отличается от iPhone. Отдал ссылку и всё.

Ставить ничего заранее не нужно: ни Android Studio, ни эмулятора.

---

## 9.2. Что такое APK

`.apk` — это один файл, внутри которого лежит собранное приложение:
скомпилированный код, картинки, шрифты и описание прав, которые оно
просит у телефона. Примерно как `.exe` в Windows, только для Android.

Обычно приложения ставят из Google Play, и тогда APK человек не видит —
магазин скачивает его сам. Но поставить APK напрямую тоже можно, просто
Android один раз переспросит: «точно ставим из этого источника?».

---

## 9.3. Почему собирает GitHub, а не ноутбук

Чтобы собрать APK, нужен **Android SDK** — набор инструментов Google
весом в несколько гигабайт. Ставить его ради одного файла не хочется.

У GitHub эти инструменты уже стоят на его машинах. Поэтому сборка живёт
в файле `.github/workflows/release-apk.yml`: при каждом пуше в `main`
GitHub берёт код, собирает APK и кладёт его в раздел Releases.

То же самое, что происходит с сайтом — только там на выходе веб-страница,
а здесь файл для телефона. Один и тот же код, две разные упаковки:

```
          код в репозитории
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
  deploy-web.yml      release-apk.yml
        │                   │
        ▼                   ▼
   GitHub Pages       GitHub Releases
   (сайт в браузере)  (файл .apk)
        │                   │
        └─────────┬─────────┘
                  ▼
        сервер на Render + PostgreSQL
```

Обрати внимание на нижнюю стрелку: **сервер один**. Аккаунт, который ты
завёл на сайте, работает и в приложении на телефоне — это тот же аккаунт
в той же базе. Ради этого в обе сборки передаётся один и тот же адрес
сервера через `--dart-define=API_URL=...`.

## 9.4. Почему файлов три, а не один

Внутри APK лежит машинный код, и он у каждого типа процессора свой.
Телефоны бывают на `arm64`, на старом 32-битном `arm` и (редко) на
`x86_64`.

Сначала мы собирали один универсальный файл — со всеми тремя внутри.
Он встаёт на любой телефон, но весит 60 МБ, и установка выглядела
зависшей: телефон долго качал файл и столько же распаковывал.

Поэтому сборка просит `--split-per-abi` — «сделай по файлу на процессор».
Получается три файла по ~20 МБ, в каждом код только для своего процессора.
Универсальный тоже остаётся, запасным вариантом.

| Файл | Кому |
| --- | --- |
| `-arm64` | почти всем: любой телефон новее 2016 года |
| `-arm32` | старым и очень дешёвым |
| `-universal` | если первые два не встали |

В Google Play такого выбора не возникает: магазин сам отдаёт телефону
нужную часть. Мы раздаём файлы сами, поэтому выбирать приходится глазами.

### Если установка подвисла

Чаще всего это **Play Защита**: Android отправляет незнакомый файл на
проверку в Google и ждёт ответа. Выключается так: Play Маркет → аватар →
«Play Защита» → шестерёнка → «Сканировать приложения» выключить. После
установки можно вернуть.

Второе по частоте — файл не докачался. Открывай APK через «Файлы» →
«Загрузки», а не из уведомления браузера: так видно настоящий размер.

## 9.5. Про подпись

Каждый APK подписан ключом — это защита от подмены: Android не даст
обновить приложение файлом, подписанным **другим** ключом.

Мы подписываем отладочным ключом, который GitHub создаёт заново на каждой
сборке. Значит, ключ каждый раз новый, и поставить новую версию поверх
старой не получится — Android откажется. Лечится просто: удалить старую
и поставить заново. Данные не потеряются, они на сервере.

Как делают по-настоящему: один раз создают свой ключ, кладут его в
секреты репозитория и подписывают им все сборки. Тогда обновления
встают поверх. Это следующий шаг, когда приложение перестанет быть
учебным — без своего ключа в Google Play всё равно не пустят.

## 9.6. iPhone: приложение без App Store

С iPhone всё иначе, и ответ здесь неочевидный.

**Чего сделать нельзя.** Собрать настоящее iOS-приложение может только
**macOS** — таково требование Apple, обойти его нечем. Дальше нужен
аккаунт разработчика (99 $ в год), а поставить файл, как APK, Apple не
разрешает вовсе: только через App Store или TestFlight.

**Что при этом можно.** Открыть сайт в Safari, нажать «Поделиться» →
«На экран „Домой“» — и на рабочем столе появится значок, который
запускает приложение во весь экран: без адресной строки, без вкладок,
со своей иконкой. От обычного приложения на глаз не отличить.

Это называется **PWA** — сайт, который умеет притворяться приложением.
И умение это не само собой берётся: его включают несколько строк в
`web/index.html` и файл `web/manifest.json`.

```html
<!-- «этот сайт можно запускать как приложение» -->
<meta name="apple-mobile-web-app-capable" content="yes">
<!-- как подписать значок на рабочем столе -->
<meta name="apple-mobile-web-app-title" content="fastwork">
<!-- какую картинку взять для значка -->
<link rel="apple-touch-icon" href="icons/apple-touch-icon.png">
```

А в `manifest.json` главное — строка `"display": "standalone"`:
«открывай меня отдельным окном, а не вкладкой». Без неё значок на
рабочем столе просто открывал бы Safari с адресной строкой.

**Честно про разницу.** PWA не получит доступ к тому, что положено
только настоящим приложениям: к фоновой работе, к некоторым датчикам.
Для fastwork это неважно — приложение и так живёт запросами к серверу.
Заметная разница ровно одна: обновления. APK нужно скачивать заново,
а PWA подтягивает новую версию сама при запуске.

Код при этом общий: тот же проект на Flutter собирается и под iOS.
Не хватает только машины и аккаунта — не кода.

## 9.7. Иконки

Иконок приложению нужно одиннадцать: Android просит пять размеров (под
разную плотность экранов), браузеру нужны свои, iPhone — свой. Рисовать
их по одной несложно; трудно потом поменять цвет и не забыть ни одну.

Поэтому иконки не лежат картинками «как нарисовалось», а собираются
скриптом [`tool/make_icons.py`](../tool/make_icons.py):

```bash
python3 tool/make_icons.py
```

Форма молнии и цвета описаны в нём один раз, а все размеры получаются
из этого описания. То же правило, что и с данными: один факт живёт в
одном месте.

Две тонкости, из-за которых иконок два вида:

- **Скруглённые** — для сайта: там картинку показывают как есть.
- **Квадратные («maskable»)** — для Android и iPhone: система сама
  обрежет их под свою форму. Дай ей уже скруглённую — получишь рамку
  внутри рамки.

И молнию мы держим ближе к середине: у обрезаемых иконок края могут
не попасть в кадр.

## 9.8. Заставка

Пока браузер скачивает и запускает приложение, экран несколько секунд
пустой. На быстром интернете этого не видно, на мобильном — вполне,
и выглядит как «не работает».

Поэтому в `web/index.html` лежит простая заставка: значок и полоска.
Убирается она не по таймеру наугад, а по событию:

```js
window.addEventListener('flutter-first-frame', function () { ... });
```

Flutter сообщает им, что нарисовал первый кадр. То есть заставка исчезает
ровно тогда, когда за ней уже есть что показать — ни раньше, ни позже.
