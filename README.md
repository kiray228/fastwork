# fastwork

Приложение для подработки по сменам: исполнитель находит смену на нужный
день и записывается, заказчик выставляет смену и отмечает, кто вышел.

Учебный проект. Пишется, чтобы разобраться, как устроено настоящее
приложение целиком — от таблицы в базе до файла, который ставят на
телефон.

## Попробовать

**Поставить на телефон: https://kiray228.github.io/fastwork/install.html**
Страница сама определит Android или iPhone.

| Где | Ссылка |
| --- | --- |
| В браузере | https://kiray228.github.io/fastwork/ |
| Android | [`.apk` напрямую](https://github.com/kiray228/fastwork/releases/latest/download/fastwork.apk) |
| iPhone | Safari → «Поделиться» → «На экран „Домой“» |
| Сервер | https://fastwork-server.onrender.com/api/health |

Вход по коду, который приходит на почту. Аккаунт общий: заведённый на
сайте работает и в приложении.

## Что внутри

```
fastwork/                 приложение на Flutter — всё, что видно на экране
├── packages/core/        данные и правила: смены, отклики, отзывы, база
└── packages/server/      сервер на Dart: HTTP-запросы, вход, отправка кодов
```

Разделение на три пакета — не для порядка в папках, а ради проверки:
`core` и `server` собраны **без Flutter**, и подключить к ним экран
просто не выйдет — сборка не пройдёт. Так правило «данные не знают про
интерфейс» проверяет компилятор, а не совесть.

| Слой | Чем занят | Про что не знает |
| --- | --- | --- |
| Экраны (`lib/`) | показать и спросить | где лежат данные |
| Хранилища (`core/data`) | правила и запросы | как всё выглядит |
| Модели (`core`) | что такое смена и сколько за неё платят | и про то, и про другое |

Одно хранилище описано интерфейсом, а выполняют его пять разных
реализаций: SQLite на устройстве, HTTP к серверу, память для тестов и две
нарочно сломанные — проверять, что экран переживёт сбой и ожидание.

## Как устроено «вживую»

```
браузер / телефон ──► сервер на Render ──► PostgreSQL
                           ▲
                    коды на почту (Brevo)
```

Сайт и APK собирает GitHub при каждом пуше в `main` — но только если
проходят тесты. Непроверенное не публикуется.

## Запустить у себя

```bash
flutter pub get
flutter test          # 128 тестов
flutter run           # без сервера — на локальной базе
```

Сервер:

```bash
cd packages/server
dart pub get
dart run bin/server.dart      # http://localhost:8080
```
